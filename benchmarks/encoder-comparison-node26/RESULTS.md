# Сравнение энкодеров: готовый TSV и Node.js 26

Измерено 22 октября 2026 на Apple M4 Max, darwin/arm64. Node.js v22.22.0, V8 12.4.254.21-node.33; Node.js v26.12.1, V8 14.6.202.34-node.40. Пути runtime сохранены в summary.json.

## CPU, мс на батч из 1000 строк

| Данные | TSV / Node 22 | Unescaped + подготовка / Node 22 | Unescaped готовые строки / Node 22 | JSON / Node 22 | JSON / Node 26 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Короткие строки (16–64 символа) | 0.355 | 0.302 | 0.270 | 0.251 | 0.230 |
| JSON-строка (~256 символов) | 0.445 | 0.389 | 0.286 | 0.357 | 0.337 |
| Текст со спецсимволами | 1.121 | 1.105 | 0.312 | 0.372 | 0.394 |
| Unicode-текст | 0.543 | 0.490 | 0.366 | 0.403 | 0.448 |
| Большая JSON-строка (~3 КБ, ASCII) | 1.162 | 1.032 | 0.680 | 1.643 | 1.381 |
| Большой текст (~3 КБ, ASCII без экранирования) | 1.026 | 1.023 | 0.590 | 1.577 | 1.325 |

Меньше — лучше. Медиана медиан 5 отдельных процессов на вариант, 7 раундов на набор. Все результаты получены заново в одном запуске.

## Контроль потребления результата

Отдельный контроль для большого чистого ASCII, с Buffer.from(body) внутри измерения; три процесса на вариант, тот же прогрев и семь раундов. Эти значения не смешиваются с основной таблицей:

| Данные | TSV / Node 22 | Unescaped + подготовка / Node 22 | Unescaped готовые строки / Node 22 | JSON / Node 22 | JSON / Node 26 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Большой чистый ASCII + Buffer.from | 1.299 | 1.222 | 0.888 | 1.827 | 1.426 |

В основной таблице результат потребляется через string.length и charCodeAt последнего символа. Контроль дополнительно материализует UTF-8-буфер целиком; он включает другую работу и не измеряет отправку по сети. Его сырые данные и диапазоны сохранены отдельно.

## Методика

- Использованы актуальные классы из src/encoders, транспилированные TypeScript в ESM с target ES2022. Копии исходников и модулей сохранены в snapshot/, SHA-256 — в summary.json. Production-код не менялся.
- Каждый набор содержит 1000 объектов по 9 полей (UUID, дата, тип, источник, целое и дробное число, boolean, nullable-строка, data). JSON внутри data остаётся строкой.
- Unescaped + подготовка включает rows.map(row => ({ ...row, data: escapeTsvString(row.data) })) на каждом батче; стоимость экранирования и создания объектов входит в измерение.
- Unescaped готовые строки получает те же подготовленные строки, созданные один раз до прогрева и измерений. Эта колонка показывает стоимость самого энкодера и исключает стоимость подготовки. Другие строковые поля безопасны для TSV во всех наборах.
- Генерация исходных объектов и строк не входит ни в одну колонку. Данные не приводились дополнительно к плоскому внутреннему представлению V8. Различия runtime могут зависеть от внутреннего представления строк и пути JSON.stringify, а не только от символов.
- Большая JSON-строка уже целиком ASCII, но содержит кавычки, требующие JSON-экранирования. Дополнительный большой ASCII-текст не содержит кавычек, обратных слешей и управляющих символов; его длина совпадает с большой JSON-строкой для каждой строки (3042–3044 символа). ASCII проверен у всех строковых полей обоих больших наборов.
- Каждый отдельный процесс измеряет один энкодер/runtime; процессы запускаются строго последовательно, порядок пяти кандидатов ротируется. Прогрев 200 мс, 7 раундов минимум по 100 мс на набор. CPU — process.cpuUsage() user+system, wall — performance.now().
- Основная таблица исключает Buffer, подсчёт UTF-8-размера, хеширование, сеть, сжатие, writer и ClickHouse. Размеры выходного TSV и JSON различаются естественным образом.
- В отдельных процессах Node 22 и Node 26 до измерений проверено точное равенство трёх TSV-путей, JSON roundtrip, совпадение SHA-256 всех выходов между runtime на шести наборах и шесть дополнительных пограничных значений. Проверки прошли. Длины, UTF-8-байты, SHA-256 — в raw/correctness22.json и raw/correctness26.json.
- Это сравнительная стоимость сериализации конкретных данных на данной машине, без утверждения, что ASCII или определённый runtime всегда быстрее. Для перехода между runtime здесь измерен только JSON-энкодер; из таблицы нельзя вывести производительность TSV на Node 26.

## Повторение

Из корня после установки зависимостей:

```sh
NODE22=/path/to/node22 NODE26=/path/to/node26 node benchmarks/encoder-comparison-node26/run.mjs
```

По умолчанию скрипт использует локальные пути исходного запуска. Node 26 взят из ранее проверенного архива; provenance сохранён в node26-provenance.json. Новый запуск обновляет snapshot/ текущими src, raw/ и отчёт.

## Дополнительный контроль: заранее материализованные ASCII-строки

Тот же большой ASCII-набор приведён через `JSON.parse(JSON.stringify(rows))` до подготовки TSV, прогрева и измерений. Это одинаковая предварительная обработка всех полей для всех пяти кандидатов. Её стоимость исключена. Текстовые значения и SHA-256 всех выходов совпали с исходным набором в обоих runtime; проверки сохранены в `raw/flat-correctness-*.json`.

| Метрика, мс на батч | TSV / Node 22 | Unescaped + подготовка / Node 22 | Unescaped готовые строки / Node 22 | JSON / Node 22 | JSON / Node 26 |
| --- | ---: | ---: | ---: | ---: | ---: |
| CPU | 1.092 | 1.017 | 0.678 | 1.679 | 0.458 |
| Wall | 0.999 | 0.932 | 0.610 | 1.662 | 0.442 |
| Разброс CPU | 1.086–1.131 | 0.929–1.215 | 0.674–0.684 | 1.591–1.762 | 0.439–0.483 |

Три последовательных процесса на кандидат с ротацией порядка, 200 мс прогрева и 7 раундов по 100 мс. Sink совпадает с основной таблицей: длина и последний символ строки. Сценарий отличается способом создания входных строк, а не набором ASCII-символов. Результат не означает, что добавление такой подготовки ускорит приложение: её цена не измерялась. Основная таблица сохранена отдельно.

Повторение после основного benchmark: `node benchmarks/encoder-comparison-node26/flat-control.mjs`. Сводка — `flat-summary.json`, отдельные раунды — `raw/flat-*.json`.

Сохранённые snapshot/ и хеши относятся к исходному измерению до переименования ClickHouseTsvRowEncoder в TsvRowEncoder. Скрипт повторного запуска использует текущее имя; основной запуск заново создаёт snapshot/ перед контрольным запуском.
